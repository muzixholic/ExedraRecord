# 서버 공개 자료로 로컬 갱신

- 날짜: 2026-10-29
- 상태: 적용
- 관련 파일: `editor/service/server-sync.mjs`, `editor/ui/server-sync.js`, `editor/service/runner.mjs`, `editor/App.swift`, `editor/Online.swift`, `editor/windows/main.cjs`

## 결정과 이유

현재 공개 사이트의 GET API와 이미지 자산으로 기억·포트레이트·캐릭터 공통 자료를 내려받는다. 별도의 서버 쓰기 API나 인증 정보를 추가하지 않는다. 기억 목록 API는 요약이므로 각 기억의 상세 API를 반드시 조회한다. 비공개 데이터와 수정 요청, 아직 구현되지 않은 도감은 동기화하지 않는다.

준비 단계에서 모든 파일을 검증해 `.editor-jobs/sync-*`에 저장하고, 확인 창에서 파일 기준 추가·교체·삭제 수를 보여 준다. 사용자가 확인하면 로컬 전용 기록을 포함한 JSON 자료를 서버 공개 목록으로 교체한다. 참조 이미지는 함께 내려받되 사용하지 않는 이미지를 자동 삭제하지 않는다.

로컬 원본의 해시를 비교해 준비 이후의 외부 편집을 감지한다. 적용 전에 교체·삭제 대상 원본과 새 파일 목록을 `data/editor-backups/server-sync/`에 백업한다. 일반 쓰기 실패는 변경한 파일을 복원한다. 강제 종료 시에는 백업을 이용한 수동 복원이 필요하다. 심볼릭 링크와 경로 이탈, 중복 식별자, 빈 서버 전체 목록, HTML 이미지 응답을 차단한다.

이미지 요청은 원래 자산 주소와 `cache: no-store`를 사용한다. 현재 실행 환경에서 이미지에 임의 쿼리를 붙인 요청의 전송 지연을 관찰했으므로 이미지에는 캐시 확인용 쿼리를 추가하지 않는다. 최대 4개씩 내려받고 일시적 오류는 최대 3회 시도한다. 파일당 이미지 제한은 50MB, 이미지 합계 제한은 512MB다.

## 제한

여러 HTTP 요청을 사용하는 다운로드이므로 서버 DB의 단일 시점 트랜잭션 스냅샷은 아니다. 외부 HTTPS 이미지 주소는 기록에 보존하지만 다른 서버에서 다운로드하지 않는다. 서버 비공개 기록을 로컬 보관해야 한다면 향후 별도 관리용 내보내기를 설계해야 한다.

## 지식 저장소

저장소 AGENTS.md에 Basic Memory 프로젝트 지정이 없고 현재 등록 목록에도 ExedraRecord가 없다. 다른 프로젝트에 기록을 섞지 않고 저장소 문서로 남겼다. shared 검색에서는 관련 결과가 없었다.
