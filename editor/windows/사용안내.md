# 윈도 기억 입력 도구

## 실행 파일

`ExedraRecordEditor-Windows-1.7.0-x64.zip`을 **폴더 전체로 압축 해제**하고 `ExedraRecordEditor.exe`를 실행합니다. exe만 따로 옮기면 실행되지 않습니다. 기본 입력 기능에는 Node.js나 브라우저 설치가 필요하지 않으며 웹 서버도 실행하지 않습니다.

윈도 10/11 64비트 일반 PC용입니다. 맥에서 윈도용 패키지를 만들고 저장·데이터 처리 테스트를 수행했습니다. 2026-10-29 사용자 PC에서 기존 1.6.1의 앱 실행과 Codex·Cloudflare 연결 확인을 검증했습니다. **새 1.7.0의 서버 자료로 로컬 갱신, 이미지 처리와 서버 배포는 윈도 실기기에서 추가 확인이 필요합니다.** ARM 윈도 전용 빌드는 포함하지 않습니다.

코드 서명은 하지 않았으므로 윈도 또는 조직의 보안 정책에 따라 실행 확인이나 제한이 발생할 수 있습니다. 회사 PC에서는 회사의 프로그램 설치·실행 정책을 따르세요.

## 처음 실행할 때

1. [GitHub 프로젝트](https://github.com/muzixholic/ExedraRecord)를 내려받거나 복제합니다. 앱 ZIP과 프로젝트 자료는 별도입니다.
2. 앱에서 `data/memories`, `public/images`, `migrations` 폴더가 들어 있는 **ExedraRecord 프로젝트 루트**를 선택합니다.
3. 기억을 선택해 편집합니다. **Ctrl+S** 또는 **기억 저장**으로 로컬 JSON에 저장합니다.

앱은 마지막으로 선택한 폴더 경로를 윈도 사용자별 앱 설정에 저장합니다. 맥에서 입력하던 기억 JSON·이미지·공통 성우 정보를 그대로 사용할 수 있습니다. 두 컴퓨터의 파일은 자동 동기화되지 않으므로 작업 전후 Git 또는 서버 자료로 로컬 갱신 기능으로 최신 자료를 맞추세요.

## 지원 기능

- 기존 기억 수정, 새 기억 입력, 스킬·한계돌파 편집
- 포트레이트 입력·수정, +0~+5 단계별 복수 효과·조건·분류 태그
- 작품 태그 및 마기아 레코드 그룹 중복 선택
- 캐릭터 공통 성우·위키 주소, 위키 검색
- PNG·JPEG 이미지 가져오기, 일러스트와 작은 썸네일 생성
- 유튜브 PV 주소 저장
- 이전 파일 자동 백업과 외부 변경 충돌 감지
- SQL 마이그레이션 내보내기
- Codex 이미지 초벌 번역과 Cloudflare 서버 반영

이미지는 최대 50MB이며 앱으로 가져오면 최대 변 3,000픽셀 PNG와 640픽셀 JPEG 썸네일을 만듭니다. 미리보기·파일 변환은 윈도 실기기에서 확인해 주세요. 원본 파일은 수정하지 않습니다. 상세 사용 흐름은 [공통 사용 안내](../사용안내.md)를 참고하세요. 맥의 ⌘S는 윈도에서 Ctrl+S입니다.

## 초벌 번역·서버 반영을 사용할 때

기본 편집은 오프라인으로 가능합니다. 온라인 기능에는 인터넷과 **해당 윈도 PC의 로그인**이 필요합니다. 맥의 인증 파일을 복사하지 않습니다.

1. Node.js LTS와 npm을 준비합니다.
2. 프로젝트 루트에서 `npm ci`를 실행해 Wrangler를 설치합니다.
3. 초벌 번역을 쓸 경우 Codex CLI를 설치합니다. npm 설치를 사용한다면 `npm install -g @openai/codex`를 실행합니다.
4. 앱의 **연결 · 기타 도구**에서 Codex·Cloudflare 로그인을 진행합니다. 필요하면 터미널에서 `codex login`, `npx wrangler login`으로 먼저 로그인한 뒤 앱을 다시 실행합니다.
5. **연결 확인** 후 초벌 번역 또는 서버 반영을 사용합니다.

초벌 번역은 이미지를 OpenAI로 보내고 Codex 사용량을 소비합니다. ChatGPT 로그인을 사용하며 앱에 별도 API 키를 저장하지 않습니다. 윈도에서는 npm의 `codex.cmd`와 설치된 `codex.exe` 탐색을 지원합니다.

서버 반영 대상은 기존 운영 사이트로 고정되어 있습니다. 실제 자료를 반영할 때만 확인 버튼을 누르세요. 취소해도 이미 완료된 서버 작업은 되돌리지 않습니다.

## 윈도에서 직접 빌드

프로젝트를 받은 뒤 터미널에서 실행합니다.

```powershell
cd editor/windows
npm ci
npm run build:win
```

결과는 프로젝트 루트의 `dist/windows/`에 생깁니다. 개발 실행은 같은 폴더에서 `npm start`를 사용합니다. 패키징에는 인터넷 연결이 필요하지만 만들어진 앱의 기본 입력 기능은 오프라인으로 동작합니다.

## 나중에 확인할 항목

- 한글·공백이 있는 경로에서 앱 실행과 프로젝트 선택
- 기억 저장, 앱 재실행 후 값 유지, 자동 백업 생성
- 작품과 여러 그룹 선택·해제·저장
- 이미지 업로드와 썸네일·미리보기
- 성우 공통 정보가 동일 캐릭터의 다른 기억에도 반영되는지 확인
- 포트레이트 화면 전환, 복수 효과·조건 입력, 강화별 값 유지
- Ctrl+S, 복사·붙여넣기, 미저장 변경 안내
- Codex와 Cloudflare 로그인 및 연결 확인
- 초벌 번역 검토·취소·편집기에 적용
- 승인한 실제 자료에 대한 서버 반영과 취소

포트레이트 화면의 **이미지로 새 포트레이트 만들기** 또는 **인게임 이미지로 초벌 입력**으로 현재 표시된 강화 단계의 정보를 추출합니다. 원문·수치·조건을 검토한 뒤 편집기에 적용하고 입수처를 선택해 저장합니다. 다른 강화 단계와 기존 일러스트·입수처·스토리 연결은 유지합니다. 윈도에서는 실제 로그인·추출·화면 동작의 실기기 검증이 필요합니다.


### 수정 요청 관리

기억·포트레이트 상세 화면 맨 아래 **수정 요청**에서 내용을 보내면 서버에 접수됩니다. 요청은 최대 2,000자이며 개인정보를 입력하지 않습니다.

입력툴 상단 **수정 요청 관리**에서 요청 일시(한국 시간), 해당 페이지, 요청사항, 처리 여부를 표로 확인합니다. 미완료·완료·전체 필터와 100건 단위 페이지 이동을 지원합니다. 미완료 요청의 **완료** 버튼은 처리 상태만 변경하며, 실제 도감 수정은 편집·저장·서버 반영을 별도로 진행합니다. 열려 있는 편집 내용은 유지됩니다.

조회와 완료 처리는 기존 Cloudflare 로그인이 필요합니다. 공개 API에서는 요청 내용 조회나 완료 처리를 허용하지 않습니다. 요청 내역은 D1의 `correction_requests` 테이블에 별도 보존되며 도감 자료를 다시 반영해도 유지됩니다. 원본 IP 주소는 요청 테이블에 저장하지 않으며 일별 해시로 일일 접수량을 제한합니다(접속자별 10건, 전체 500건). 최초 설치·업데이트 시 `0011_correction_requests.sql` 마이그레이션을 적용합니다. 입력툴 서버 반영도 테이블과 색인을 자동 준비합니다.


### 캐릭터 그룹과 바리에이션

표시 캐릭터명과 `character_group`을 분리합니다. 악마 호무라는 아케미 호무라 그룹, 얼티밋 마도카는 카나메 마도카 그룹으로 자동 연결합니다. 그 외 캐릭터는 자기 이름을 기준으로 별도 그룹이 되며, 기본 정보의 **캐릭터 그룹**에서 다른 그룹을 직접 선택할 수 있습니다. 이미지 초벌 입력으로 이름을 채운 경우에도 이 규칙을 적용합니다. 저장하면 그룹 연결을 기록하고, 상세 화면의 같은 캐릭터 다른 기억은 그룹 전체를 표시합니다.

성우 이름과 문서 주소도 그룹 공통값을 사용합니다. **이 기억만 성우 개별 지정**을 선택하면 해당 기억의 성우를 별도로 저장하며 그룹 공통 정보를 변경하지 않습니다. 수동 성우 가져오기 버튼으로 그룹의 기존 값을 복사할 수도 있습니다. 기존 그룹·개별 지정은 초벌 번역 적용 후에도 유지됩니다.


### 윈도 연결 확인 개선 (1.7.0)

외부 Codex·Wrangler 작업은 입력툴에 내장된 Electron 대신 PC에 설치된 Node.js로 실행합니다. 일반 설치 경로와 fnm의 기본 별칭·설치 버전·멀티셸 경로를 탐색하며, 임시 링크를 실제 설치 경로로 정규화합니다. 프로젝트 안의 Wrangler 설치 방식은 유지됩니다. `연결 확인`에는 사용한 Node.js·Codex·Wrangler 경로와 실제 실패 원인이 표시됩니다. 기본 오프라인 편집에는 Node.js가 필요하지 않습니다.

터미널에서 설치·로그인은 정상인데 앱만 실패했다면 새 ZIP을 별도 폴더에 압축 해제해 실행하고 기존 프로젝트 폴더를 선택합니다. 기존 JSON·이미지와 로그인은 유지됩니다. 연결 실패 시 표시된 경로와 오류 문구를 확인합니다.


## 서버 자료로 로컬 전체 갱신

기억 또는 포트레이트 화면의 왼쪽 `서버 자료로 로컬 갱신`을 누릅니다. 기억 화면에서는 `연결 · 기타 도구`를 펼치면 있습니다.

1. 편집 중인 내용은 먼저 저장합니다.
2. 앱이 기존 공개 사이트의 기억 상세·포트레이트·캐릭터 공통 정보·연결 이미지를 내려받아 검증합니다. 이 단계에서는 로컬 원본을 바꾸지 않습니다.
3. 추가·교체·삭제될 파일 수를 확인합니다. `갱신하지 않기`를 누르면 기존 자료가 유지됩니다.
4. `백업 후 로컬 전체 갱신`을 누릅니다. 로컬에만 있는 기억·포트레이트도 제거되어 서버 공개 목록과 같아집니다. 로컬에서만 입력 중인 자료가 있다면 반드시 백업과 교체 범위를 확인하세요.
5. 완료 후 현재 도감이 다시 열립니다. 완료 메시지에 백업 경로가 표시됩니다.

Node.js와 인터넷 연결이 필요합니다. 서버의 공개 조회를 이용하므로 Codex·Cloudflare 로그인과 Codex 사용량은 필요하지 않습니다. 비공개 자료·수정 요청·향후 스토리 등 다른 도감은 대상이 아닙니다. 코드·로그인 설정·사용하지 않는 이미지 파일은 유지합니다.

다운로드 실패 시 원본은 그대로 유지합니다. 준비 이후 로컬 JSON·캐릭터 공통 정보·교체 대상 이미지가 달라지면 다시 준비하도록 안내합니다. 교체 중 일반 오류는 자동 복원합니다. 교체 중에는 앱을 종료하지 마세요. 강제 종료·전원 차단은 자동 복원이 보장되지 않습니다.

### 갱신 전 자료로 수동 복원

백업은 프로젝트의 `data/editor-backups/server-sync/sync-*` 폴더에 보관합니다. 백업에는 교체·삭제 대상의 기존 파일, `복원목록.json`, 성공 시 `갱신완료.json`이 있습니다. 사용하지 않는 이미지는 원래 자리에 유지되므로 백업하지 않습니다.

복원할 때는 앱을 닫고 백업 폴더의 `data`와 `public` 아래 파일을 같은 프로젝트 상대 경로로 복사합니다. `복원목록.json`의 `absent`에 나열된 파일은 갱신 당시 새로 생긴 파일이므로 제거합니다. 이후 앱을 다시 열어 자료를 불러옵니다. 복원 직전에 추가 편집한 자료가 있다면 그 자료도 별도로 보관하세요.
